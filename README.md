## Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь Saboteur аялал байв: curl-ээр UI-г тойрч илгээсэн бараг бүх буруу хүсэлтийг API хүлээн авсан бөгөөд зөвхөн энэ аялалаар BUG-06 (эвдэрсэн JSON-д 200 OK) олдож, BUG-02, BUG-03, BUG-07-г API түвшинд баталгаажуулсан. Couch Potato аялалаар хоосон болон зөвхөн зайтай талбар (BUG-02), буруу он (BUG-03) олдсон бол Supermodel аялалаар тоолуурын алдаа (BUG-01), оны таслалтай формат (BUG-04), урт оролтоор хүснэгт эвдрэх (BUG-05) согог илэрсэн. Charter-аас гадуур санамсаргүй олдсон зүйл нь аппыг нээмэгц «Нийт ном» тоолуур буруу байсан явдал, мөн UI-аар нэмсэн он string, API-аар нэмсэн он number хэлбэрээр хадгалагдаж байгаа зөрүү юм. Хайлт том/жижиг үсэг ялгахгүй ажиллаж байгаа нь спецификацийн дагуу зөв болохыг шалгав. Шалгагдаагүй үлдсэн зүйлс нь Устгах үйлдэл ба түүний товчны өнгө (дэлгэцийн зурагт ногоон харагдаж байгаа нь «улаан» байх шаардлагаас зөрж магадгүй), мессежүүдийн үсгийн алдаа, хуудасны бүх линк, зохиолчоор хайх үйлдэл — эдгээрийг дараагийн session-ий charter болгоно. Playwright автомат тест BUG-01 (тоолуур = мөрийн тоо), BUG-02, BUG-03, BUG-07 (буруу оролтын дараа мөр нэмэгдэхгүй байх), BUG-06 (API статус код 400 байх) согогийг тодорхой assertion-оор барих боломжтой байсан. Харин BUG-04 (оны формат), BUG-05 (хүснэгтийн байршил эвдрэх), товчны өнгө зэрэг харагдацын согогийг тест бичигч урьдчилан тааж assertion бичээгүй бол зөвхөн хүний нүдээр олох байсан. Иймээс автомат тест нь мэдэгдэж буй дүрмийг дахин шалгахад, exploratory тест нь хэн ч урьдчилан бодоогүй зан төлөвийг илрүүлэхэд илүү тохиромжтой гэж дүгнэв.
